Compression engine

lossless · full GFA semantics · CPU + GPU
Compression ratio — higher is better
Decompression throughput, MiB/s — log scale
Compression reaches 1355 MiB/s on CPU (32 threads, end-to-end CLI wall time) and 4843 MiB/s on GPU. GFAz wins ratio on every dataset while decompressing faster than Zstd — and unlike SQZ and GBZ it preserves the complete GFA.

Traversals are >90% of a GFA and collapse under iterative 2-mer grammar compression; everything else gets columnar, type-specific encoding. Both directions are linear-time and fully parallel.

Phase 1 recovers snarls from topology alone (biconnected decomposition, O(V+E), decodes zero haplotypes). Phase 2 streams each haplotype once through a boundary state machine; a reverse boundary pair normalizes inversions.
A pangenome graph does not have to be unpacked to be queried.

Outputs match the baselines: growth reproduces Panacus’ curve exactly, deconstruct agrees with vg to within 0.2% of records, pav matrices are structurally identical to odgi’s. On the 358/369 GB HPRC graphs vg and odgi cannot load the input at all. Open: whole-genome pav still exceeds memory there — its node-set index is not yet compressed.
